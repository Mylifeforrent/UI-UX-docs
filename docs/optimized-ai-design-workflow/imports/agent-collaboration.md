# Agent 协作与人机边界

← 返回 [原型先行全流程主文档](prototype-first-workflow.md)

AI 提效，人工定夺。这份文档划清"哪些交给 AI、哪些必须人工拍板"，避免两类灾难：把决策权交给 AI（业务权限做错），或把执行细节全揽在自己身上（丧失效率）。

## 核心原则

1. **AI 负责"生成与穷举"，人工负责"裁决与取舍"。** AI 能一口气列出 8 种状态、20 个组件，但哪个状态是真实存在的业务分支、哪个交互符合你的用户，只有你知道。
2. **先计划，后执行。** 任何"生成页面""写代码"的动作，都要求 Agent 先输出计划（路由、组件拆分、数据来源、测试清单），人工确认后再动手。这是全流程最便宜的纠偏点。
3. **一次一任务。** 单轮聚焦一件事，质量高、易回滚。

## 人机边界表

| 环节 | AI 提效（可放手） | 人工定夺（必须亲自判断） |
| --- | --- | --- |
| 竞品分析 | 逐屏描述结构、罗列可借鉴点 | 每条"借鉴/避免"是否适合自己的用户 |
| 业务建模 | 生成角色/对象/任务五列表草稿 | 权限矩阵、风险任务的失败恢复是否正确 |
| 交互设计 | 穷举页面状态、列组件清单 | 哪些状态是真实业务分支、优先级排序 |
| 原型生成 | 生成界面、补状态、迭代文案 | 信息层级、危险操作防误触、视觉基准 |
| PRD 反写 | 从原型+评审记录起草 PRD | 权限、验收标准、"明确不做"范围 |
| 代码生成 | 按组件清单实现、写 fixture | 权限校验、键盘焦点、响应式断点 |

## 必须人工确认的清单

无论 AI 生成得多完整，以下四类**一定要人工过一遍**（对应 [原型到代码](../06-engineering-workflow/prototype-to-code.md) 的返工源）：

- **权限**：无权限态是只读还是完全不可见？操作按钮在无权限时禁用还是隐藏？
- **危险/不可逆操作**：是否二次确认？是否强制填理由？失败能否逐条恢复？
- **键盘焦点与无障碍**：Tab 顺序、焦点可见、快捷键、屏幕阅读器标签（见 [Design Token](../04-design-system/tokens.md) 与组件清单的键盘行为列）。
- **响应式**：桌面与手机端的关键差异（如表格→摘要卡片）是否符合真实使用场景。

## 让 Agent 先计划的标准句式

```text
先输出实现计划：路由、组件拆分（对照组件清单，禁止新建同义组件）、
每个状态的数据来源、测试清单。等我确认后再写代码。
```

计划里如果出现"新建一个和 OrderTable 类似的表格""临时用一个灰色"这类信号，就是要拦下来的地方。

## 常见误区

| 误区 | 后果 | 纠正 |
| --- | --- | --- |
| 把业务权限判断交给 AI | 原型好看但权限流全错 | 权限永远人工定夺 |
| 不让 Agent 先出计划直接写码 | 大段返工、难回滚 | 先计划后执行 |
| 人工事必躬亲写每个状态文案 | 效率丧失 | 穷举交给 AI，裁决留给人 |
