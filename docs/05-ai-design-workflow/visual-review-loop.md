# 视觉评审闭环

视觉验收是可重复的工程循环，不是一次主观判断。

```text
实现 → 固定视口截图 → 按区域对照原型 → 记录问题
→ 按严重级别排序 → 一次只改一类问题 → 同视口再截图
```

## 固定检查顺序

1. 布局与容器：边线、侧栏、表格、主按钮是否对齐。
2. 视觉层级：首屏是否能找到主任务，低频信息是否抢注意力。
3. 间距、字体与截断：长内容是否换行、截断或提供详情。
4. 颜色与状态：状态是否同时有文本/图标，Token 是否一致。
5. 交互反馈：加载、成功、错误、焦点和危险操作是否可理解。
6. 响应式与无障碍：1440、1024、768、390 视口和键盘主流程。

问题描述要可执行，例如“390px 下详情标题覆盖关闭按钮，标题应换行并保持关闭按钮固定可触达”，不要写“感觉不够高级”。每条问题附截图、复现视口、期望结果和严重级别，写入 [视觉验收记录](../templates/visual-acceptance.md)。

截图应使用脱敏 fixture，记录浏览器、版本、提交号和视口。修复后回归同一状态及相邻状态，避免只修正常态而破坏空态或错误态。
