# Agent 协作

把 Agent 当作不同职责的协作者，而不是一个万能按钮。共享同一套文档和命名，减少产品分析、设计和代码之间的翻译损失。

```text
产品分析 Agent：角色、任务、边界和状态
设计 Agent：布局、视觉方向和原型变体
评审 Agent：层级、可用性、无障碍和一致性
Coding Agent：组件、路由、数据和测试
```

## 共享上下文

每次协作至少提供 [UI Brief](../templates/ui-brief.md)、[页面清单](../templates/page-inventory.md)、[组件清单](../templates/component-inventory.md)、[Token](../04-design-system/tokens.md)、API 契约和固定视口截图。修改请求说明目标、约束、验收条件和不能改变的内容。

## 人与 AI 的边界

人负责业务取舍、品牌判断、权限、危险操作、敏感数据和最终验收；AI 负责探索、重复实现、状态枚举和局部修正。不要让 Agent 直接决定安全策略、审计语义或未经确认的产品范围。

## 数据护栏

- 使用脱敏或合成数据，避免在 Prompt、截图和日志中出现密钥、个人敏感信息和客户隐私。
- 给外部工具最小权限，只开放需要的文件或 Frame；不要默认分享整个代码库和设计文件。
- 生成的依赖、网络请求和权限判断必须人工审查；原型能运行不代表生产安全。
- 每次重要修改留下 Prompt、输入上下文、输出版本和验收结果，便于回滚和复盘。
