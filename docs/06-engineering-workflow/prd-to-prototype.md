# PRD 到原型

这一步把业务描述转成可评审的界面结构。先定义任务和状态，再让 AI 或 Figma 生成视觉方案。

## 输入与产出

输入：PRD、角色、业务对象、权限规则、接口草案和已知限制。

产出：

1. [UI Brief](../templates/ui-brief.md)
2. [页面清单](../templates/page-inventory.md)
3. [组件清单](../templates/component-inventory.md)
4. 用户流程、页面状态矩阵和低保真线框
5. 可在 Figma/Make 中评审的高保真原型

## 操作顺序

### 1. 拆解业务

把 PRD 改写成下面五列，避免直接从技术接口推页面：

| 项目 | 示例 |
| --- | --- |
| 角色 | 运营专员、主管、审计员 |
| 对象 | 订单、审批任务、客户 |
| 高频任务 | 筛选订单、查看详情、批量审批 |
| 风险任务 | 撤回、驳回、删除 |
| 完成条件 | 状态更新、有审计记录、失败可恢复 |

补齐每个任务的入口、前置条件、成功反馈和失败恢复。权限不足不是异常分支，而是页面设计的一种状态。

### 2. 建立页面清单

用 [页面清单模板](../templates/page-inventory.md) 记录路由、主动作、数据依赖和所有状态。订单工作台的最小范围是：

```text
/orders              订单列表
/orders/:id          订单详情
/orders/new          创建订单
/orders/:id/edit     编辑订单
/approvals           审批队列
```

### 3. 先画灰度结构

先确认容器、信息层级和操作顺序，再进入 [Design Token](../04-design-system/tokens.md) 和品牌色。订单列表至少应能回答：当前筛选条件、结果数量、单行主动作、批量操作和下一页在哪里。

```text
页面标题 + 创建订单
筛选条件                              已选 3 项  批量审批
结果摘要
订单号 | 客户 | 金额 | 状态 | 更新时间 | 操作
--------------------------------------------------
分页 / 每页数量
```

### 4. 生成原型并评审

把 [UI Brief](../templates/ui-brief.md)、[组件清单](../templates/component-inventory.md)、Token 和真实长度文案一起提供给 Figma/Make 或 Coding Agent。要求原型覆盖默认、加载、空数据、无结果、错误、无权限和成功状态；不要只生成一张“正常态”截图。

评审时使用 [设计评审记录](../templates/design-review.md)，先评审主任务、信息层级和危险操作，再评审颜色和装饰。

## 可复制 Prompt

```text
你是企业 SaaS 产品设计师。请根据以下订单审批 PRD 输出：
1. 角色、对象、任务、权限矩阵；
2. 页面清单（路由、入口、主动作、数据依赖）；
3. 每个页面的默认/加载/空数据/错误/无权限状态；
4. 列表、详情、审批的灰度线框；
5. 需要复用的组件及其状态。

约束：优先扫描、比较和重复操作；使用仓库既有 Design Token；危险操作必须可恢复；不要新增未说明的业务能力。
输出使用 Markdown 表格，最后列出 5 个需要产品确认的问题。
```

## 完成标准

- 每个主流程都有入口、完成条件、失败恢复。
- 页面、组件和状态都能在模板中找到对应记录。
- 原型中的层级、操作和异常状态通过 [视觉验收](../templates/visual-acceptance.md) 记录。
- 产品评审通过后，才进入 [原型到代码](prototype-to-code.md)。
