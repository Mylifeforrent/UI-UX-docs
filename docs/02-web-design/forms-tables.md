# 表单与表格

这是企业产品中最容易返工的两类界面。先写用户决策和数据状态，再决定控件。

## 表单决策表

| 场景 | 设计规则 | 工程影响 |
| --- | --- | --- |
| 必填字段 | 标签和必填含义在输入前可理解 | HTML `required` 与服务端校验一致 |
| 格式复杂 | 提供示例、即时校验和修复文案 | 错误绑定字段，不清空合法输入 |
| 长表单 | 按决策顺序分组，必要时保存草稿 | 路由离开保护、草稿恢复 |
| 服务端错误 | 表单摘要 + 字段错误 | 处理 4xx，不只显示通用 Toast |
| 危险修改 | 显示影响和确认 | 幂等、权限和审计必须由后端保证 |

```text
订单信息
客户*        [________________________]
金额*        [____________] CNY
交付日期*    [2026-08-30  v]
备注         [________________________]
             [保存草稿] [提交审批]
```

提交失败时保留输入，焦点移到第一个错误；离开有未保存修改的页面时，明确提供继续编辑、保存草稿和放弃三种选择。

## 表格决策表

| 问题 | 选择 |
| --- | --- |
| 用户要比较什么 | 高频字段放首屏，金额右对齐，状态用文本 + 色彩 |
| 结果如何缩小 | 搜索、状态、日期筛选；条件和排序进入 URL |
| 如何连续处理 | 行选择、选中数量、批量操作、处理中和部分失败 |
| 低频信息在哪 | 列设置或详情页，不能让首屏无限变宽 |
| 没有数据怎么办 | 首次空态引导创建；过滤无结果提供清除筛选 |
| 手机怎么办 | 改成摘要列表或可控横向滚动，保留关键字段和主动作 |

## 分页、排序与批量操作

分页需要显示当前范围和总量，切换页时保留筛选和排序。排序图标要有可访问名称和当前方向。批量操作前显示影响范围，执行中防止重复提交，完成后显示成功数量、失败原因和重试/刷新入口。

表格和表单的状态矩阵见 [响应式与页面状态](responsive-states.md)，API 的分页、部分失败和权限语义见 [真实数据接入](../06-engineering-workflow/real-data-integration.md)。
