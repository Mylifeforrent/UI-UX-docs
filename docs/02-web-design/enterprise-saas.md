# 企业 SaaS 页面

企业产品服务于扫描、比较和重复操作。稳定的容器、清晰的状态和可预测的操作比装饰性卡片更重要。

## 页面骨架

```text
全局导航/侧栏
└── 页面标题 + 面包屑 + 主动作
    ├── 摘要或关键指标
    ├── 筛选与批量操作
    ├── 主内容（表格、看板或详情）
    └── 分页、日志或下一步操作
```

## 订单列表示例

```text
订单                         [创建订单]
待处理 28  | 本周金额 ¥1.2M
[状态 v] [客户搜索________] [更新时间 v]    已选 3 项 [批量审批]
订单号       客户                         金额      状态       更新时间  操作
ORD-1024     Acme 国际供应链（华东区域）   ¥128,000   待审批     10:30    查看
ORD-1025     北辰科技                    ¥0         草稿       昨天     编辑
                                              [分页 1 2 3] [每页 20]
```

设计决策：首屏保留用户比较所需字段；低频列进入列设置；筛选条件、排序和分页进入 URL；行操作保持一个主动作，其余放菜单；批量操作显示选中数量和处理结果。

## 常见页面类型

| 类型 | 首要任务 | 必备区域 | 高风险点 |
| --- | --- | --- | --- |
| 列表 | 找到并批量处理 | 筛选、排序、表格、分页、空态 | 选择范围、部分失败 |
| 详情 | 理解上下文并做决定 | 摘要、属性、时间线、关联对象 | 权限、并发更新、危险操作 |
| 创建/编辑 | 准确录入并保存 | 分组字段、校验、草稿、离开保护 | 长表单、服务端错误 |
| 审批/监控 | 识别异常并采取行动 | 状态、责任人、时间、异常、钻取 | 告警噪声、误操作 |

先用 [信息架构](information-architecture.md) 明确对象和任务，再用 [页面模式](../04-design-system/patterns.md) 复用结构。页面落地前填写 [组件清单](../templates/component-inventory.md)。

## 信息密度控制

密度不是单纯缩小字号。先保证对齐线、列优先级和可读行高，再决定是否压缩。每个区块只保留一个视觉重点；用留白和对齐表达关系，少用嵌套卡片和无意义边框。
