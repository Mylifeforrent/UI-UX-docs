# App 信息架构

移动端不是桌面后台的缩小版。移动端信息架构应围绕一个短时、高频、可中断的任务组织；业务对象和权限可以与 Web 共用，入口和内容层级要重新设计。

## 从 Web 提取任务

以 [Web 工作台](../08-practice-projects/web-workbench.md) 为例，移动端只保留主管最常做的“查看待审批订单并处理”，不搬运列设置、复杂报表和低频管理功能。

| 任务 | 频率 | 风险 | 移动端优先级 |
| --- | --- | --- | --- |
| 查看待审批 | 高 | 中 | 首屏入口 |
| 批准/驳回 | 中 | 高 | 详情主动作 |
| 编辑订单 | 低 | 高 | 引导回 Web |
| 查看审计记录 | 低 | 中 | 详情按需展开 |

## 移动导航

```text
待办（默认） | 通知 | 我的
      ↓
待审批列表 → 订单摘要 → 风险详情 → 批准/驳回
```

每个入口说明当前状态和未读数量，但不要用红点替代文字。通知只负责把用户带到任务，进入页面后重新拉取权限和最新数据。

## 中断与离线

移动端必须设计来电、切后台、弱网和系统回收后的恢复：保留已加载摘要，标注数据时间；提交中返回要显示处理状态；恢复后检查版本冲突；未完成的驳回意见提供草稿或明确放弃选择。
