# 平台适配

共享业务模型、文案和 [Design Token](../04-design-system/tokens.md)，但不强行共享所有交互。平台适配的目标是遵循用户已经形成的系统习惯。

## 对比表

| 议题 | iOS 倾向 | Android 倾向 | 设计检查 |
| --- | --- | --- | --- |
| 顶层导航 | Tab Bar | Bottom Navigation | 高频入口少于 5 个 |
| 返回 | 导航栏和边缘返回 | 系统返回键/手势 | 返回栈有明确目标 |
| 确认 | Action Sheet/Alert | Dialog/Bottom Sheet | 危险动作说明影响 |
| 权限 | 解释后按需请求 | 解释后按需请求 | 拒绝后可在设置或页面恢复 |
| 系统区域 | 刘海、Home Indicator | 状态栏、导航栏 | 安全区不遮挡内容 |
| 通知 | 通知中心和摘要 | 通知栏和渠道 | 通知是入口，不是唯一状态源 |

## 通用工程约束

- 主要控件保持可触达尺寸，间距不因平台缩放而互相遮挡。
- 处理横屏、字体放大、深色模式、系统键盘和低内存恢复。
- 权限、隐私和生物识别失败都要有解释、取消和恢复路径。
- 网络状态和数据更新时间可见；不能把本地缓存伪装成最新数据。
- 使用平台原生控件时保留语义和辅助技术行为；自绘控件要补齐焦点、读屏和键盘等价操作。

从 Web 迁移到移动端时，先完成 [App 信息架构](information-architecture.md)，再在 [移动端练习](../08-practice-projects/mobile-companion.md) 中记录哪些内容保留、删除或改成按需展开。
